# 项目计划

课程：综合设计与实践 C。题目：缩微滴滴（RoboTax / MiniDiDi）。周期：第 1–16 周，第 8 周中期检查，第 16 周期末答辩。

## 1. 总体策略

1. **集成优先**：孤立的模块拿不到"良"。所以先让整个系统跑起来，之后每周都在能跑的系统上加功能。
2. **接口先行**：`docs/protocol.md` 是各模块并行开发的合同，改动前先在组内讨论。
3. **必做求稳，挑战求精**：必做决定能不能拿良，挑战决定能不能拿优。中期之后集中做 2–3 个挑战项，并用实验数据证明效果。
4. **文档随做随写**：每个阶段产出对应的文档，期末只做汇编。
5. **按现场全自主演示来设计**：一键启动、设备自动连接、事件按场景脚本自动触发、自带网络。

## 7. 现场演示要点

- 自带路由器，给设备分配固定 IP。校园网常开启终端隔离，设备之间可能互相连不上；Windows 防火墙要提前放行 8080、9000、9001 端口。
- 一键启动（已实现）：`scripts/start_demo.bat` / `start_demo.sh` 依次启动服务端（运行 `demo` 场景脚本）→ Matlab 5 车
  （没装 MATLAB 时自动改用 Python 模拟车）→ 模拟手机 → 浏览器 2D 主界面和 3D 视图（自动巡游）。之后全程不用碰电脑：
  路障、未知障碍、早晚高峰、订单潮都由场景脚本按时间自动触发，约 6 分钟一轮、循环播放。
- 手机 App 打开后会自动连接上次的服务端（设置里可关），考核时只需打开 App、拿着走。
- 考核前用 `scripts/start_server.sh --scenario perception` 等单独排练每个情节。
- 教室里收不到 GPS 信号，手机位置要靠行人航位推算，再设一个比例尺，在教室里走动就能让手机车在城市地图上跑起来。演示前在讲台附近做一次"设位置""对方向"；没人走动时可以用 App 的"模拟行走"（手机平放在桌上，转动手机就能转弯）。
- 演示流程控制在 5 分钟以内，准备好备份录像和备用电脑。
- PPT 正文 5 页可以这样排：系统总体 → 数字世界与调度（带数据）→ Matlab 孪生车与控制避障 → 手机与 Gazebo → 挑战亮点与评估结论。
